# 自动语言：按应用切换输入语言

状态：设计草案，2026-11-07。本文描述拟实现的 macOS 功能，尚未接入输入法；界面收敛为“最近十个应用添加 + 已配置规则列表”。

## 目标与范围

青简保持为系统当前输入源，切换应用时按规则设置青简内部的输入语言。典型配置是 VS Code、Terminal 使用英文，ChatGPT 独立应用使用中文。少量临时需求继续通过青简现有快捷键手动切换。

本项目以青简 fork 为主体。提取或移植 InputSourcePro 的应用识别、应用列表和规则配置相关处理，集中放进独立模块；不嵌入它的完整应用，不保留它的菜单栏、设置界面、Core Data 存储或系统输入源切换流程，也不新增第二个常驻应用。

第一期只做 macOS、应用级，目标语言来自当前平台可用的输入模式，不限定为中英布尔值。当前 macOS 壳已经接入中文、英文和越南语（见 `ThirdInputMethod`、Host 模式状态与 IMK 越南语处理）；原型以这三项模拟平台能力。日语罗马音已有 Core 和 Android 实现，但尚未接入 macOS，不能据此把日语列为 macOS 可用选项。

这里的“应用”按稳定的 bundle identifier 匹配，不按 PID；同一应用的所有窗口与输入框共用规则。浏览器不同网页、VS Code 编辑区与集成终端不能分别设置。网站、窗口标题和输入框识别留待有实际需求时讨论。

“输入语言”指实际输入模式，与设置程序的界面语言、候选词的辅助译文语言、全拼或双拼方案无关。各处下拉框统一读取平台能力列表，新增输入语言时自动出现在默认语言、刚才应用和规则编辑中；不得直接使用辅助译文的 `Language` 或 `learning_languages()` 充当输入能力表。该能力列表是实现提案，当前代码尚无统一的输入模式枚举。

## 已有接入条件

- macOS 的 `activateServer:` 已能取得输入客户端 bundle ID：`apps/macos/src/imk/controller/mod.rs`。`apps/macos/src/imk/controller/display.rs` 的 `note_application` 还会在按键时补查，适合首次激活尚未取得标识的情况。
- 实际用户中英状态由 `apps/macos/src/host/mode/switch/mod.rs` 中的 `Host::english_mode` 与 `ModeSwitch` 决定。
- 不能直接以 `Engine::set_english_mode` 充当用户模式开关：`apps/macos/src/imk/controller/text.rs` 每键将其写成英文候选分流状态。自动切换必须经过 Host 的统一模式设置通路，更新输入状态、菜单栏提示与候选显示。
- `crates/qingjian-platform/src/config/apps.rs` 当前只控制哪些应用显示英文候选，并不设置该应用的输入语言。
- `default_english` 与 `remember_mode_per_app` 虽已有配置字段，macOS 的支持表仍标为待实现。不能把当前 Windows 的按应用记忆描述成 macOS 已有能力。

## 使用规则

功能默认关闭；升级后保持原有行为。开启后，应用显式规则优先，没有规则或选择“跟随默认”的应用使用本页的全局默认语言。全局默认初始为中文，可选当前平台支持的输入语言。

| 事件 | 行为 |
|---|---|
| 从应用 A 进入应用 B | 在 B 的第一个输入字符处理前，应用 B 的规则或全局默认 |
| 同一应用内切窗口、输入框或重复 IMK 激活 | 不重应用默认，不覆盖手动状态 |
| 在 B 中手动切换语言 | 本次停留期间保持，不写回 B 的默认规则 |
| 从 B 切到其他普通应用后再回 B | 重新应用 B 的默认规则 |
| B → 青简设置 → B，规则未改 | 保持 B 的临时手动状态；设置窗口不构成一次新的普通应用访问 |
| 在设置中改了 B 的规则，再回 B | 在 B 下一次安全获得输入焦点时应用新规则一次；不在设置窗口里修改 B 的输入会话 |
| 暂时拿不到应用标识 | 保持当前模式，等待首次补查成功；不把未知应用误记成另一应用 |
| 关闭自动切换 | 停止规则执行，保留当前模式，继续使用原有手动切换 |
| 系统切到了青简以外的输入源 | 不切回青简、不管理其他输入源；用户切回青简后再按实际输入应用求值 |

退出某个应用不删除规则；重新打开后按 bundle ID 命中。状态去重必须与“离开后重入”分开：不能只记最后一个有 IMK 输入的应用，否则 A → 没有输入的 B → A 会漏掉重入。平台 adapter 以普通应用激活事件维护访问边界，IMK 客户端用于确认实际输入目标和首键兜底；两者不能各自重复执行一次规则。

青简设置、输入法自身及短暂系统输入面板不作为普通规则目标。“刚才使用的应用”是进入设置前最近一次激活的合格普通应用，不要求先输入文字；该目标在设置获焦前冻结，不能被设置程序自身覆盖。例如 Terminal 输入 → Finder 未输入 → 设置，快捷目标与最近列表首位都应为 Finder。若没有有效目标，本页显示“先切换到要设置的应用，再回来”，不展示或要求用户填写进程标识。

“按应用默认”与“记住应用上次模式”是两种策略。第一期采用前者，不在后台自动学习用户手动状态，也不复用 `remember_mode_per_app` 的含义。

## 设置页

在青简设置侧栏“高级”与“实验功能”之间增加“自动语言”，页面标题也用“自动语言”，沿用现有字体、主题、控件与保存方式。标题和短标签承担说明；复杂语义放在 ⓘ，不在页面铺技术说明。第一期按 `apps/settings/src/support/` 的支持表只在 macOS 显示，其他平台登记为待实现。

页面共有的内容如下：

1. “按应用自动切换”总开关；关闭时仍允许编辑规则与预览，状态明确显示“已关闭”，不会暗示规则正在执行。
2. “未设置的应用”下拉：当前平台可用的输入语言，定义全局默认；这里不再提供“跟随默认”，避免循环含义。
3. “刚才使用的应用”：名称、图标、已确认的当前模式、命中规则；对应打开设置前最近激活的普通应用，不冒称设置程序仍在该应用输入。若 IMK 尚未确认该应用模式，显示“当前模式未知”，不能沿用另一个应用的状态。右侧“进入时”下拉显示可用输入语言及“跟随默认”，选择即保存；未配置时显示“选择输入语言”，不预先生成规则。已有规则直接更新，不设固定“设为中文 / 设为英文”按钮。
4. 已配置规则列表：每个应用一行，右侧下拉与刚才应用共用语言选项，另有移除；末尾“添加应用…”只打开最近十个应用选择面板。
5. “切换提示”开关与“预览”按钮，复用青简已有的中 / 英提示样式；预览不执行真实语言切换，也不新增光标跟随浮窗。

本期只保留这一种列表形式，不增加语言分组、应用详情布局或布局切换。最近应用用于容易找到目标，已配置列表用于维护规则；二者有不同生命周期。

### 添加、修改与移除

选到想配置的应用是本页最重要的体验。日常路径是“刚才使用的应用 → 下拉选择输入语言”，不先让用户理解进程；只有配置其他最近应用时才打开选择面板。

输入法在本次运行期间维护最近使用的十个应用，按应用激活先后排列；同一 bundle ID 再次出现时移到最前，超过十个淘汰最旧项。只记录正常用户应用，过滤 Helper、后台代理、青简自身、设置程序与临时系统输入面板。无法识别应用标识时不加入；PID 只用于即时查询，不作为历史或规则键。

“添加应用…”打开一个轻量选择面板：

1. 显示最近十个应用，刚才使用的应用排最上，每行显示图标、名称和已配置状态。
2. 点选一个应用后，在共用语言下拉中选择目标语言或“跟随默认”并确认。已有规则的应用显示“已设置：英文”等状态，带入原设置并更新原规则，不复制。
3. 找不到目标或没有历史时显示“先切换到要设置的应用，再回来”。用户切过去再回设置后，该应用自然出现在首位。

不提供搜索、运行进程全列表、已安装应用扫描、原生 `.app` 选择器或手填 PID/bundle ID。原型只需完整操作“打开最近应用 → 选应用 → 选语言 → 添加”，以及“刚才使用的应用 → 下拉选择语言”快捷路径。

选择“刚才使用的应用”时直接带入其标识。添加面板对未配置应用使用“跟随默认”作为初始选择，用户可改为任一可用语言再确认。同一 bundle ID 只允许一条规则。同名但不同 bundle ID 的应用可通过悬停补充标识以便区分。

修改下拉即按青简现有方式保存；“跟随默认”保留应用行，方便以后再调。移除只删除规则，不退出或卸载应用。最近十个应用是本次运行的内存记录，重启清空，不记录窗口标题、输入内容或应用访问时间线。已配置规则则持久保存；MRU 淘汰、应用退出或历史清空都不删除规则。应用未运行、被移动或暂时卸载时仍保留已配规则，失效图标用通用应用图标替代。

### 预览的含义

界面同时区分“配置目标语言”和“当前实际模式”。用户临时手动切中文时，可以出现“进入时：英文；当前：中文（手动切换）”，不能把预期结果当成真实状态。

提示由实际输入模式生成完整文字，例如“已切换到中文输入”“已切换到英文输入”“已切换到越南语输入”，并使用对应的短标记。仅实际语言变化时，在屏幕固定角落显示约 0.8 秒，默认开启；连续进入相同语言的应用不重复弹出。以后平台支持日文输入时自动沿用相同格式，不在提示逻辑写中英二分支。提示不跟随光标，不引入光标探测。

预览只展示提示效果，关闭提示不会关闭规则。交互原型使用模拟应用、模拟模式和内存配置，明确标为原型；它不能读取真实前台应用、修改系统设置或切换真实输入语言。

原型源码位于 `apps/settings/prototypes/auto-language/recent-apps.prototype.html`，仅用于选型与交互验证，不接入生产设置程序。设置窗口下方的“试一下实际使用顺序”是原型演示控制，用来模拟进入应用与手动切换；不会作为正式设置项交付。其已配置规则也仅在内存中，刷新后重置。

## 模块归属与接口

以下目录是实现提案，尚未创建：

| 位置 | 职责 |
|---|---|
| `crates/qingjian-auto-language/` | 平台无关的规则求值与本次访问状态；输入应用事件、手动切换、配置修订，返回切换决定与状态 |
| `apps/macos/src/auto_language/` | macOS adapter：应用激活监听、IMK 目标确认、名称图标、最近十个应用、事件去重、运行状态查询；不处理词库、排序或文本变换 |
| `apps/settings/src/auto_language/` | 本页状态、最近应用选择、规则编辑和提示预览；页面渲染通过现有 pages 入口接入 |
| `crates/qingjian-platform/src/config/auto_language/` | 独立 TOML 分节的配置类型、默认值、校验与转换 |

规则模块只需一个小接口：接收事件、规则与可用输入模式，返回 `Keep` 或“将当前输入应用设为指定输入模式”的决定，并给出应用标识与原因。语言使用稳定的模式标识；不能用 `bool english` 表达全部语言。平台调用方负责实际模式设置；测试也从这个接口驱动。它不创建系统监听、不读文件、不持有 IMK 对象，也不新增一般化插件框架。

Host 只暴露一条完整的模式设置通路给手动与自动切换使用，保证清除待定 Shift 点击、更新实际语言状态、处理越南语等模式进出、刷新菜单栏和提示的行为一致。实际应用前再次核对输入目标，过期的 A 决定不能切换到 B；提示仅在实际模式改变时出现。

对青简原有代码的接线集中在：workspace 依赖、配置总表、设置页注册与平台支持表、macOS 启动监听与退出清理、IMK 激活和首键补查、Host 手动模式通知及统一模式设置。候选、词库、排序和翻译模块不需要为应用规则改动。独立目录只能减少冲突，不能消除这些接线点；后续同步上游要针对它们做小范围回归。

## 配置与设置进程通信

规则仍保存到青简唯一的 `config.toml`，不引入 InputSourcePro 数据库或第二份持久配置。拟采用下列独立分节；名称和序列化细节在实现时确认，不是现在可用的配置：

```toml
[auto_language]
enabled = false
default_language = "chinese"
show_switch_hint = true

[[auto_language.rules]]
app_id = "com.apple.Terminal"
display_name = "Terminal"
language = "english"

[[auto_language.rules]]
app_id = "com.microsoft.VSCode"
display_name = "Visual Studio Code"
language = "english"
```

`display_name` 只是显示缓存，匹配只看 `app_id`；图标与 `.app` 路径由平台查询，不参与规则匹配。`language` 使用输入模式的稳定键，例如 `chinese`、`english`、`vietnamese`；应用规则另可为 `default`。同一应用重复、空标识、未知语言值应在保存时拒绝并在对应行提示；热加载失败沿用上一份有效规则。已知模式若在当前平台暂不可用，保留原规则并标记不可用，运行时保持当前模式，不静默改成另一语言；平台能力恢复后再正常执行。默认语言不可用时也保持当前模式并报告状态，不制造跨平台配置丢失。

第一期选择精确 bundle ID 匹配，不增加通配符、优先级或多条叠加规则。配置保存使用青简现有更新路径，避免覆盖其他设置项；设置进程与手改文件并发时需按当前文件合并本分节，不能把旧整份配置写回。

输入法和设置程序是不同进程。最近十个应用及当前实际模式由输入法持有，设置程序在本页打开期间通过本机只读查询取得内存快照。为遵守 MRU 不落盘的范围，不将最近应用写进配置、缓存文件或日志；拟使用当前用户私有的本地 socket，请求仅允许查询状态，不执行任意命令。端点本身不是历史数据文件，生命周期与输入法进程一致。

响应包含协议版本、输入法本次启动标识、最近十个应用及刚才激活目标、该目标已确认的实际模式（或未知）、命中规则与配置修订号；不包含输入内容、窗口标题或浏览历史。设置程序只在该页可见时请求，不在按键路径等待通信。查询失败、版本不兼容或输入法未运行时显示“状态不可用”，不把陈旧状态展示成实时结果。最终传输方式、端点位置与退出清理在通信包中确定并验证，保持本地、只读、无历史落盘的约束。

## InputSourcePro 的提取方式

本地参考仓库为 `../InputSourcePro`。已经核查的入口包括：

- `Input Source Pro/Models/ApplicationVM.swift`：应用激活监听、识别、去重、规则变更后求值。
- `Input Source Pro/Persistence/AppRule.swift`：以 bundle ID 关联规则、应用名称与图标。
- `Input Source Pro/Models/PreferencesVM+AppCustomization.swift`：应用配置相关处理。

按功能移植适合当前范围的处理，不把这些 Swift 文件连同 UI、Combine、AX 窗口观察、Core Data 和系统输入源执行一起复制。已有的 IMK 客户端识别优先复用，`NSWorkspace` 应用激活事件补齐“离开后返回”的访问语义。

本期设计不请求辅助功能、屏幕录制权限，不安装全局键盘监听；只读取应用激活与输入客户端信息，不读取别的应用窗口内容。最近应用随事件更新，不枚举全量进程。具体系统版本与应用环境的权限表现仍需真机验收，不从系统文档推导“任意环境都零权限”。开发的主要复杂点是首字符时序、手动优先与设置窗口焦点处理，而不是维护一张进程列表。

实际开始移植时，在独立模块的来源记录里写明 InputSourcePro 上游地址、选用的真实提交、原文件路径、哪些处理直接移植、哪些按青简重写，并保留相应版权和许可文本。当前只做设计，不填写未经确认的提交号，也不把“参考设计”说成“已复用代码”。移植代码留在 GPL 适用模块，不搬入 bamboo-slip 等双许可 UI 基础库。

## 兼容性与待开发验证项

- **实现前必须解决的模式接口设计**：目前 macOS 在不启用单击 Shift 时会从 Caps Lock 读取中英模式。仅改一个布尔值不足以让自动规则生效。推荐 Host 提供独立于 Shift 快捷键开关的显式模式 setter，自动开启时由内部持久模式作为来源，Shift 若启用则修改同一模式，Caps Lock 负责大小写。不能增加“必须先勾单击 Shift”的产品限制，也不能静默修改快捷键配置。原先依靠 Caps Lock 手动切中英的用户如何保留可用的手动路径，以及退出自动时如何与物理 Caps 状态无跳变交接，仍需工程设计和真机验证；当前草案未解决，UI 原型不代表兼容性已完成。验收判据是保留配置好的手动快捷键语义、自动开关不造成未预期语言跳变、大小写正确、关闭 Shift 仍能执行应用规则。该项未解决前不交付运行功能。
- 用户关闭“中英文切换”时仍固定中文，自动规则暂停；本页开关受依赖限制并通过 ⓘ 提示。不能让自动模块绕过该总开关。
- 输入组合串不能跟随规则跨应用上屏。切换模式和会话的时序沿用 IMK 原有会话结束语义；规则只在目标会话确认且可安全应用时执行。未完成组合时编辑规则应等待安全时机，不能强制提交到新应用。
- 手动进入任一可用语言时，本次停留继续尊重手动模式；下一次普通应用重入才执行目标语言规则。越南语的自动进入不能静默修改用户的双击 Shift 目标配置；须单独验证该输入模式的完整进入/退出、未完成组合和返回手动模式流程。
- 英文候选名单继续独立生效。Terminal 切英文不等于开启英文候选，规则页面不改候选名单。
- 首键兜底必须在字符分流之前求值。重复激活、异步应用信息及迟到事件不得导致首字错模式或多次提示。
